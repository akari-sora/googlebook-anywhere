# Release tools

The tag commit updates `docs/RELEASE-NOTES.md` in place. The package gate checks fixed lines 1–3 and scans every line and every Markdown segment (paragraph, list item, table row, or heading, also inside blockquotes) of the entire file without guessing section or code-fence boundaries:

- Line 1 must be exactly `# Googlebook Anywhere <tag>` (for example `# Googlebook Anywhere v0.2.1`). Remove ` (未發布)` from the title.
- Line 2 must be empty.
- Line 3 must be exactly `<!-- release-status: released -->` (during development it is `unreleased`). A released line anywhere else does not count.
- Across the entire file, only plain Markdown is accepted (raw HTML tags, comments, or `<https://...>` autolinks outside code spans anywhere except the status comment on line 3 are refused; any numeric character reference `&#`, with or without `;`, or named character reference `&name;` is refused; link targets `](...)` with spaces, quotes, parentheses, or a title, or split over lines, are refused; a backtick inside a link target, reference-style links `[text][label]` and link definitions `[label]: url` are refused (use `[text](url)`); escaped `\[`, `\]`, `\(` and `\)` are refused; HTML comments `<!--` are refused except the status comment on line 3; image `![`, GitLab inline-diff `{+ +}`, `[+ +]`, `{- -}` and inline-math `` $` `` / `` `$ `` markers are removed before the segment scan; escaped square brackets are refused as above), and none of the listed unpublished phrases may appear on any line or within any Markdown segment — paragraph, list item, table row, or heading, also inside blockquotes (including inside backtick fences, `~~~` fences, indented code blocks, or older-version sections; there are no exemptions): in addition to the per-line check, each segment (split at blank or `>`-only lines, setext underlines / thematic breaks, list items, table rows, and headings) is scanned with link targets (`](...)`) and one-line reference labels (`][...]`) removed across two case-insensitive Latin views (one with markup deleted and whitespace/line breaks collapsed to single spaces; one with markup and `-_/` replaced by spaces and whitespace/line breaks collapsed) and one CJK view (with markup, whitespace, and line breaks deleted). Limits: a phrase can be refused across joined table cells or sentences in the same segment — rephrase if so; deliberate obfuscation (such as look-alike letters or invisible characters) is out of scope, and the tag commit is reviewed. Remove the title's `(未發布)` and the introduction's 「這一版還沒有發布。」. The gate also refuses 未發布, 還沒有發布, 還沒發布, 待發布, 即將發布, 沒正式發布, 沒有正式發布, 未正式發布, 未發佈, 還沒有發佈, 還沒發佈, 未发布, and the case-insensitive Latin phrases unreleased, unpublished, and not yet released.

Set `GBOS_REQUIRE_PRIVATE_SCAN` as a CI/CD variable in the private GitLab project settings, not in this repo. Unset, empty after trimming surrounding whitespace, `0`, and `false` (case-insensitive, after trimming whitespace) leave a genuine public export free to skip. Any other non-empty value, including `1` and `true`, forces the scan: a missing `tools/release/private-patterns.txt` fails. Do not mark the variable "Protect variable". Protected variables are omitted on unprotected branches and merge request pipelines, so those pipelines would run without the scan. Leave the variable unset on public CI.

`tools/release/make-public.sh <commit> <dir>` writes `tools/release/PUBLIC-EXPORT` into the exported tree: the 40- or 64-hex source commit SHA and a newline (it refuses a source commit that already contains the marker). `tests/stick/public-export-test.py` skips only for a tree with a well-formed marker whose private paths (`research/`, `tools/harness/kano-env.local.sh`, `tools/release/private-patterns.txt`) are not in the git index (or not in the work tree when there is no index), whose history never touched the pattern file or the personal settings file, and whose marker does not name a commit in that clone. A private checkout that contains the marker is refused.
