# KANO、HX370、ROG Ally：成果及剩餘目標

更新：2026-11-07。目標是讓 **KANO、HX370、ROG Ally 三台都能穩定使用 Googlebook，並共用一套安裝、保留資料更新與復原流程**。先補齊 KANO 已可用內建系統的缺陷，同時推進另外兩台；下列六項仍有未完成部分（OPEN），不代表每項從零開始。

## 已可用的內建系統基準

KANO 內建系統在 2026-10-29 已從 16452207 slot a 保留資料更新至 16658739 slot b，使用者回報可用。桌面與帳號登入、螢幕與亮度、鍵盤、觸控板、Wi-Fi、喇叭和內建麥克風均已有實機成果。10 月 29–30 日的內建版本亦有基本睡醒、闔蓋／開蓋與鍵盤喚醒結果；整機 S0ix 尚未達成。更新時比對的套件清單、帳號數、主要設定、鎖定狀態及主要使用者檔名為 `RETENTION_OK`，尚未涵蓋所有檔案內容、App 資料及完整還原。

接下來優先修相機、EC／鍵盤背光與感測器、闔蓋省電，再保留資料更新回內建系統。USB 候選的失敗或未測項要分開記錄，不能抹去上述內建成果，也不能據此認定原本正常的功能已損壞。基準來源見 [KANO 狀態](STATUS-KANO.md)及 [v0.3.0 實機更新證據](VERIFICATION-v0.3.0.md#kano-實機證據)。

HX370 與 ROG Ally 可評估將系統裝在各自記憶卡上；先確認讀卡機驅動、韌體開機能力、效能、睡醒及資料保留，再決定安裝位置。這是可選安裝方式，尚非已驗收支援；既有記憶卡資料不因加入目標而獲准清除。

## 最新 USB 候選範圍

本輪續測：包含相機初始化診斷 `0010` 的新映像已建好，51 項映像檢查、完整雜湊、最終 8 個相機檔案、開機設定綁定、擁有者 AVB 簽章及 10 個分割區描述子均已離線核對通過，尚未寫入 USB 或實機開機。它提供錯誤記錄，不代表相機已修好。音訊探針四次實機嘗試都在安裝前停止；後續短查詢成功，但長查詢對照測試逾時，診斷連線原因仍未釐清，尚無播放／錄音結果。詳細範圍與映像雜湊見 [KANO 狀態](STATUS-KANO.md)。既有 PIN 略過、機型名稱及約 40 GiB 資料區的實測結果保持原範圍，未新增重開後資料保留或睡眠省電通過證據。

## 剩餘目標與完成標準

### 1. 修正測試資料空間與首次使用問題

2026-11-06 相機候選補測：以原生 PIN 頁的 Skip／Skip anyway 到達桌面，Model 與裝置名稱正確；診斷連線恢復後讀到資料檔案系統 42,919,243,776 bytes，當次 USB 身分及掛載讀值與開機快照一致。本候選尚未重新開機驗證檔案與設定保留。以下較早的 R6 結果仍保留其原適用範圍。

目前進度：R6 USB 實機讀到資料分割區 42,921,344,512 bytes，F2FS 檔案系統 42,919,243,776 bytes，當時可用 26,567,700,480 bytes；型號與預設裝置名稱均為 Acer Chromebook Spin 714。首次設定未輸入 PIN，依序選擇 Skip 及 Skip anyway 後到達桌面。另一次唯讀取樣在前後讀到相同前景 user 10，其 `user_setup_complete` 與全域 `device_provisioned` 均為 1；取樣不能排除兩次讀取之間瞬間切換，也不能取代首次設定畫面或憑證資料庫驗證。

之後完成一次正常關機再開機，延後的唯讀核對確認仍從同一支 USB 執行，F2FS 容量仍為 42,919,243,776 bytes、機型名稱正確。但最初診斷連線等待逾時，後續確認睡眠並喚醒後才讀取成功，穩定性仍待修正。重開後前景為 user 0；另查確認先前 user 10 仍存在、設定完成旗標為 1，但取樣時未執行，不能據此證明所有設定或檔案保留；資料、設定、自訂名稱保留及其他完成標準仍待驗證。以下核取項維持未勾選。

之後唯讀觀察到 user 0 的登入程式；一次一般使用者切換的連線回傳 255，當次結果仍為未知，沒有重送。後續同次開機的前後取樣均為 user 10，並讀到該使用者的 NexusLauncher 活動；焦點紀錄無法確認，不能代表畫面可用。獨立核對同一 USB 身分及鎖定狀態已清理。這不證明解鎖、檔案或設定保留，也不代表冷開機問題已修復。

主線共用維護控制器仍只接受 KANO／HX370。離線清單與診斷封裝已加入可選的 Ally 資料包與機型規則介面，三機封裝須有完整匹配的建置紀錄、獨立雜湊及非空規則，並拒絕未列入清單的殘留 Ally 規則；合成測試通過。Ally 分支已有核心、手把與 CPU 相容性管線，但實際機型設定仍為草稿，尚無可供此三機流程使用的已驗收映像。共用安裝器的實體目標目前限定 NVMe，尚不能選記憶卡；HX370 USB 設定亦封鎖 SD 控制器驅動。這些是需要補齊的程式限制，不能當成硬體無法從卡開機的結論。

來源進度：內部 `apply_observed_block` 已實作目標事實核對、整段獨占持有、封印 ESP 規劃、寫前重查及穩定裝置身分的續跑綁定。自建 loop 完整執行 6 項通過，另 1 項因寫前觀察不一致停止，同一來源及測試的單項重跑通過；原因未重現，保守拒絕仍保留。支援範圍及 caller 信任限制見[共用安裝碟](UNIVERSAL-INSTALLER.md#受觀察區塊裝置的保留資料更新後端開發中)；可信機型到產物映射及維護准入尚未整合，完整備份還原也未接入。

新增的內部新裝核心會重建磁碟與所有分割區 GUID、複製非 userdata 分割區、只清除 userdata 前 16 MiB，並將 GPT userdata 延伸至目標可用末端；檔案系統由 Android 首次開機格式化，尚非已格式化或完成容量驗收。來源須由 caller 獨立確認為該機型可信的原始產物，其他分割區、ESP 及舊磁碟空隙仍可能含資料；這不是安全抹除，也沒有 durable 新裝復原或自動回退。Linux 小型一般檔案與相關測試共 76 項通過；特權測試啟動器的來源別名鎖定未通過審查並已停用，新裝的 5 項自建 loop 測試尚未執行。

建置端另已加入映像與機型設定的建置紀錄；共用診斷打包時可提供兩份獨立核對的紀錄雜湊，檢查它們與清單、映像及實際封裝的機型設定一致。57 項合成測試及 7 個實際發布程式片段案例通過；紀錄仍是未簽署的建置自述，輸入涵蓋不完整、資料乾淨狀態未證明，不能作為完整來源認證、寫入授權或實機驗收。既有映像保持原狀，未補寫歷史證明。

另已在共用維護系統的測試差異檔，以非 root、TCG 虛擬 NVMe 完成六個合成案例：兩種模擬機型各自新裝及更新、錯誤 catalog 與未知 DMI 的指定階段拒絕。宿主獨立核對 GPT、GUID、userdata、舊槽與新槽邏輯內容及開機設定；拒絕案例的 NVMe 寫入為 0，各案例的 USB 寫入及 unmap 為 0，測試媒體邏輯比對與原始來源完整雜湊再核對通過，26 項純測試也通過。測試控制器先排除序列登入服務延後掛載的啟動競爭，保留原後端檢查；這不代表先前 host-loop 觀察差異的原因已證實。本輪重用準備好的測試媒體，未安裝原媒體內的正式雙資料包，也未測 Android 開機、失敗復原或實體裝置。

R5 映像未改動且不含這些後端，實體 USB／NVMe 與雙機驗收均未新增；以上完成標準維持未勾選。

共用媒體可以攜帶各機型獨立核心與資料包；不要求用一個 Android 核心支援所有機器。驗證期間保留原維護碟，是目前的回復安排，不是每種機型永久需要一支碟。

### 6. 整理可重用的硬體驗收入口

已整併盤點、睡醒採集、離線判讀與共用精簡電源讀取：`--daily-inventory` 在既有受驗證、持鎖的 USB 試開流程內執行固定唯讀查詢；互斥的 `--idle-wake` 執行固定單次自然睡醒背光採集，限制被動輪詢及同一已驗證位址的一次重連，缺漏或身分不明時進入既有 UNKNOWN hold；`manual-guard.py assess-idle-wake DIR` 判讀證據，不執行證據目錄裡的程式。精簡電源讀取先保留 Android dumpsys 的結束狀態，再傳回狀態區段，完整性仍由既有 guard 判讀。另已整併已開機 USB 的固定 recovery 入口：先核對持鎖、AP 記錄器、同次開機身分及電源狀態，再依確認的狀態執行有限的喚醒與背光恢復；狀態不明時維持鎖定。整合來源經完整及增量審查，131 項離線測試與靜態檢查通過；這些是合成證據、實際測試檔案鎖及模擬傳輸測試。新版入口尚未部署或以新映像實測，採集來源的真實性、照片與其他硬體項目仍須獨立確認，本項仍只部分完成。

- [ ] 完成其餘固定腳本的入口整併，並部署與實測已整併的盤點、睡醒和 recovery 入口；保留身分及停止檢查。
- [ ] 保留實際測試版本與證據索引。舊 R4 額外腳本及實機證據仍保留歸檔；新增通用睡醒採集來源不等於已部署或取得新的實機結果，推送目前分支也不等於本項完成。

## 下一輪順序

先前 R8 曾在測試 USB 上完成 PIN 頁的略過流程並到達桌面；一般 Not now 路徑仍有問題。新的相機候選已在同一支 USB 上完成上述原生 PIN 略過流程並到達桌面，機型名稱亦正確；相機預覽／拍照實測未通過。無線診斷已恢復，當次 USB 身分、掛載讀值與約 40 GiB 資料檔案系統已核對；接著定位相機 HAL 初始化失敗，並測音訊及背光曲線，接續補齊其餘周邊、睡眠與省電驗收；重用已核對的建置輸入。其間可平行完成共用安裝器的程式整合；只有一個主代理操作實機。以既有內建成果為基準補缺陷，待候選功能與回復條件成立，再保留資料更新內建系統；共用媒體接續完成三機驗收。只有實體插拔、換卡或其他無法遠端完成的必要操作才請使用者協助；等候期間繼續其餘可自動完成的工作。

全部上述產品與實機條件有對應證據，才可將「日常可用＋共用安裝救援碟」標為完成；提交數、離線測試數或診斷映像開機不替代這個標準。
