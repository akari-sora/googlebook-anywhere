# KANO、HX370、ROG Ally：成果及剩餘目標

更新：2026-11-09。目標是讓 **KANO、HX370、ROG Ally 三台都能穩定使用 Googlebook，並共用一套安裝、保留資料更新與復原流程**。先補齊 KANO 已可用內建系統的缺陷，同時推進另外兩台；下列六項仍有未完成部分（OPEN），不代表每項從零開始。

## 已可用的內建系統基準

KANO 內建系統在 2026-10-29 已從 16452207 slot a 保留資料更新至 16658739 slot b，使用者回報可用。桌面與帳號登入、螢幕與亮度、鍵盤、觸控板、Wi-Fi、喇叭和內建麥克風均已有實機成果。10 月 29–30 日的內建版本亦有基本睡醒、闔蓋／開蓋與鍵盤喚醒結果；整機 S0ix 尚未達成。更新時比對的套件清單、帳號數、主要設定、鎖定狀態及主要使用者檔名為 `RETENTION_OK`，尚未涵蓋所有檔案內容、App 資料及完整還原。

接下來優先修相機、EC／鍵盤背光與感測器、闔蓋省電，再保留資料更新回內建系統。USB 候選的失敗或未測項要分開記錄，不能抹去上述內建成果，也不能據此認定原本正常的功能已損壞。基準來源見 [KANO 狀態](STATUS-KANO.md)及 [v0.3.0 實機更新證據](VERIFICATION-v0.3.0.md#kano-實機證據)。

HX370 與 ROG Ally 可評估將系統裝在各自記憶卡上；先確認讀卡機驅動、韌體開機能力、效能、睡醒及資料保留，再決定安裝位置。這是可選安裝方式，尚非已驗收支援；既有記憶卡資料不因加入目標而獲准清除。

**ROG Ally：** 第六版完整候選映像通過全部 53 項 QEMU／映像檢查，並獨立讀回核對；SHA-256 `85e334eb6fa36af6980587e9acd2807cdb46df6fba1ae8869850dfef040286c4`。實機開機、手把、Wi-Fi 與記憶卡皆未驗收。現有 Bazzite 系統實讀到 GL9755 讀卡機（`17a0:9755`）；針對該控制器與實機子系統 ID 的選用診斷模組已建置，版本字串與 99 項匯入符號 CRC 均與原核心資料相符；在使用相同 Ally 核心的隔離 QEMU 測試中，該模組及四個相依模組均已載入，五者回傳值均為 0；此測試沒有實體讀卡機，也未驗證 Android 的載入政策。後續使用相同核心與候選政策的隔離 QEMU 測試發現，81 項、1039 bytes 的 `module_blacklist` 遭核心以 `string parameter too long` 拒絕，五個選定模組均實際載入；先前 53 項檢查不能證明黑名單生效。建置程式現會拒絕超過 1024 bytes 的參數，尚未完成修正版核心或映像。靜態讀回仍確認第六版候選的兩個 ESP 開機項目包含 `sdhci_pci`、`sdhci_acpi`，但參數存在不代表封鎖有效；串接的三份 initramfs archive 中，實際 first-stage 載入清單也未加入 SDHCI。vendor 雖有相關模組，這不代表 Android 會載入；其載入政策、實體 PCI 偵測、記憶卡、從卡開機及共用媒體安裝均未驗收。

**HX370：** 已歸檔映像的核心缺少 Realtek RTS525A 的 RTSX PCI 驅動；新核心與唯讀 update_engine 修正版已完成完整映像建置，通過 60 項 QEMU／映像檢查及獨立讀回；SHA-256 `1e72800a9859651bffcee8696a7f7d664892e082a53b00809d4772964dead61a`。修正版的實際二進位已在隔離 QEMU 測試映像中通過 14 項介面結果與全部 16 項檢查，包括子程序死亡後回收 64 個 callback 名額，以及 32 組不同 callback 的並行綁定／解除；該測試使用僅供測試的權限規則及臨時金鑰，正式環境客戶端權限仍未驗證，也不能由有限測試排除所有競態。另已直接盤點正式映像的四個系統分割區，確認服務啟動設定與相關文字權限規則，並解析出系統服務及設定程式內的 UpdateEngine／UpdateEngineStable 靜態呼叫；這仍未證明實際執行時的權限、動態載入的其他客戶端或 Binder 呼叫成功。共用維護核心與實機支援、從卡開機及卡上安裝均未驗收；共用安裝器的實體目標目前限定 NVMe。

來源進度：內部 `apply_observed_block` 已實作目標事實核對、整段獨占持有、封印 ESP 規劃、寫前重查及穩定裝置身分的續跑綁定。自建 loop 完整執行 6 項通過，另 1 項因寫前觀察不一致停止，同一來源及測試的單項重跑通過；原因未重現，保守拒絕仍保留。支援範圍及 caller 信任限制見[共用安裝碟](UNIVERSAL-INSTALLER.md#受觀察區塊裝置的保留資料更新後端開發中)；可信機型到產物映射及維護准入尚未整合，完整備份還原也未接入。

新增的內部新裝核心會重建磁碟與所有分割區 GUID、複製非 userdata 分割區、只清除 userdata 前 16 MiB，並將 GPT userdata 延伸至目標可用末端；檔案系統由 Android 首次開機格式化，尚非已格式化或完成容量驗收。來源須由 caller 獨立確認為該機型可信的原始產物，其他分割區、ESP 及舊磁碟空隙仍可能含資料；這不是安全抹除，也沒有 durable 新裝復原或自動回退。Linux 小型一般檔案與相關測試共 76 項通過；特權測試啟動器的來源別名鎖定未通過審查並已停用，新裝的 5 項自建 loop 測試尚未執行。

建置端另已加入映像與機型設定的建置紀錄；共用診斷打包時可提供兩份獨立核對的紀錄雜湊，檢查它們與清單、映像及實際封裝的機型設定一致。57 項合成測試及 7 個實際發布程式片段案例通過；紀錄仍是未簽署的建置自述，輸入涵蓋不完整、資料乾淨狀態未證明，不能作為完整來源認證、寫入授權或實機驗收。既有映像保持原狀，未補寫歷史證明。

另已在共用維護系統的測試差異檔，以非 root、TCG 虛擬 NVMe 完成六個合成案例：兩種模擬機型各自新裝及更新、錯誤 catalog 與未知 DMI 的指定階段拒絕。宿主獨立核對 GPT、GUID、userdata、舊槽與新槽邏輯內容及開機設定；拒絕案例的 NVMe 寫入為 0，各案例的 USB 寫入及 unmap 為 0，測試媒體邏輯比對與原始來源完整雜湊再核對通過，26 項純測試也通過。測試控制器先排除序列登入服務延後掛載的啟動競爭，保留原後端檢查；這不代表先前 host-loop 觀察差異的原因已證實。本輪重用準備好的測試媒體，未安裝原媒體內的正式雙資料包，也未測 Android 開機、失敗復原或實體裝置。

R5 映像未改動且不含這些後端，實體 USB／NVMe 與雙機驗收均未新增；以上完成標準維持未勾選。

共用媒體可以攜帶各機型獨立核心與資料包；不要求用一個 Android 核心支援所有機器。驗證期間保留原維護碟，是目前的回復安排，不是每種機型永久需要一支碟。
